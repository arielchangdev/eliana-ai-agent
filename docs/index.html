What it is

A red-team assessment agent that grows — within limits it cannot cross

Eliana is a conversational, self-hosted agent (Python + a hosted LLM on its free tier) that performs authorized security assessment: it orchestrates multiple reconnaissance and analysis tools, classifies findings against MITRE ATT&CK, and reports results through a Telegram runtime and a live dashboard. The interesting part isn't that it talks — it's the discipline around autonomy. Eliana improves its own assessment behavior through a verifiable learning loop, while every capability stays behind a dual authorization gate, an evaluation-mode allowlist, and a human in the loop. It assesses and classifies; it does not weaponize.

Three pillars

Autonomous, self-improving, and kept on a leash

Pillar 1

Autonomous architecture

Multi-tool orchestration across a phased assessment profile, with conversational operation over a Telegram runtime and a live status dashboard.

Pillar 2

Bounded self-improvement

An assessment memory feeds a verifiable learning loop that measurably changes the agent's behavior — proven, not simulated.

Pillar 3

Human-in-the-loop authorization

A dual authorization gate, an evaluation-mode argument allowlist, and ATT&CK classification (not attack execution) keep scope enforced in code.

The proof

Learning you can verify, not just claim

CLOSED-LOOP-PROVEN

The hardest thing to trust in a “self-learning” agent is whether it's actually learning or just looking like it. Eliana's loop is verifiable end to end: seed a past assessment experience, run again, and observe the behavior change. In the proven case, a tool that previously sat 5th in the execution order moved up to 3rd after the agent recalled relevant prior experience — a concrete, reproducible shift in behavior driven by what it learned.

Engineering highlights

What makes it trustworthy

Orchestration

Phased multi-tool profiles

Builds a staged assessment across multiple tools, with finding de-duplication so repeated signals collapse into one.

Classification

ATT&CK mapping, not attacks

A curated rule table maps findings to MITRE ATT&CK techniques for reporting — classification as a defensive artifact, never exploitation.

Learning

Verifiable assessment memory

Stores past experience and recalls it to inform future runs, gated so attack-oriented terms never drive behavior.

Guardrail

Dual authorization gate

Every assessment passes two independent authorization checks before any tool runs — scope enforced in code, not policy docs.

Guardrail

Evaluation-mode allowlist

Tool arguments are restricted to a vetted evaluation set; intrusive orchestration is excluded by design.

Cost

Zero cost, testnet-only

Runs entirely on free tiers; the wallet integration is testnet-only, carrying no real-money risk.

War stories

The hard part wasn't the AI. It was the wiring.

Six bugs ate most of the build time — none were about intelligence, all were about plumbing. Full engineering write-up in the blog.

1. Scan engine never touched the database

A component can look wired up and still be talking to nothing.

2. SSH session built but never connected

Constructing a client isn't the same as opening the connection.

3. Money math on floats

Use Decimal for value — float precision drifts silently.

4. The “learning” was fake

A feature that quietly pretends to work is the worst kind of bug.

5. systemd %h pointed at the wrong home

Service specifiers resolve against the unit's user, not yours.

6. De-identification fallback missed a path

Scrubbing has to cover every path, not the happy one.
